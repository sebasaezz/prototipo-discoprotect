## Arquitectura y operación

El S22 emite un identificador ficticio opaco, el S25 cierra IsoDep y resuelve contra la API sujeta a autorización de guardia en el evento. Fastify/SQLite es la fuente de autoridad. AppAsistente verifica cuenta y credencial antes de editar. Las escrituras comparten una versión optimista entre ficha y contactos, mantienen borradores aparte y exigen revisión tras 409 o resultado incierto. [Arquitectura](../architecture.md) · [API REST](../api-contract.md) · [Modelo SQLite](../data-model.md) · [Contrato NFC](../nfc-contract.md)

Instala desde la rama H3 los APK debug, usa la base ficticia y configura el servidor en ambas apps con la IP LAN del PC. Para migración, seed, requisitos Node y Android y rutas de compilación, sigue el [README](../../README.md). Para firewall, reconexión y ejecución en los Samsung, sigue los guiones de [H2](../h2-lan.md) y [H3](../h3-integration.md). La interfaz sigue el [Design System](../design-system.md).

## Límites y riesgos vigentes

El prototipo usa cuentas y fichas ficticias. El acceso demo de asistentes y los PIN de guardia y organizador tienen alcance académico. La información es autodeclarada y el prototipo carece de validación para uso clínico o productivo. Los procedimientos médicos y de emergencia siguen siendo responsabilidad del personal competente. HTTP debug circula en claro y solo se usa en una LAN controlada. Release exige HTTPS. El modo conectado depende del servidor local, el firewall y la comunicación entre clientes. NFC está sujeto a hardware, bloqueo, ajustes y Secure NFC. H4 deberá resolver la consistencia de identidad y credencial en todas las transiciones.
